# PRD — نبض (Nabz)
### ایجنت تصمیم‌ساز نگه‌داشت مشتری برای خرده‌فروش‌های ایرانی

نسخه: ۰.۱ (پیش‌نویس) — تاریخ: ۱۴۰۵/۰۵/۰۱

---

## ۱. مسئله

خرده‌فروش‌های ایرانی (به‌ویژه فروشگاه‌های اینستاگرامی و آنلاین‌شاپ‌های کوچک و متوسط) داده‌ی زیادی از مشتری دارند:
تاریخچه‌ی خرید، سبد رهاشده، مکالمات دایرکت/واتساپ، واکنش به استوری، زمان آخرین تعامل.

اما تصمیم «با این مشتری خاص، امروز، از چه کانالی، با چه پیشنهادی صحبت کنم؟» را ندارند.
راه‌حل رایج، کمپین یکسان برای همه است: تخفیف عمومی، پیامک مناسبتی. نتیجه:
- مشتری‌هایی که بدون تخفیف هم می‌خریدند، تخفیف می‌گیرند → افت حاشیه سود.
- مشتری‌های در آستانه‌ی ریزش، پیام مناسب و به‌موقع نمی‌گیرند → از دست می‌روند.
- مشتری‌هایی که نباید زیاد پیام بگیرند، اسپم می‌شوند → خستگی و آن‌فالو.

## ۲. چشم‌انداز محصول

نبض یک **لایه‌ی تصمیم** روی داده‌ی موجود خرده‌فروش می‌نشیند (نه یک CRM یا ابزار پیامک جدید).
ورودی: داده‌ی مشتری/سفارش/سبد/مکالمه. خروجی: برای هر مشتری — **بهترین اقدام بعدی**
(چه کسی، چه زمانی، از چه کانالی، با چه پیشنهادی، با چه متنی).

نبض جایگزین CRM یا ابزار ارسال پیامک/دایرکت نیست؛ روی آن‌ها می‌نشیند و «مغز تصمیم» را فراهم می‌کند.

## ۳. مخاطب و سگمنت اول (MVP)

- **سگمنت اول:** فروشگاه‌های اینستاگرامی و آنلاین‌شاپ‌های B2C با حجم چند صد تا چند هزار مشتری فعال.
- **کانال‌های اصلی این سگمنت:** دایرکت اینستاگرام، واتساپ، پیامک.
- **چرا این سگمنت:** حجم بالای فروشنده، وابستگی شدید به تعامل دستی، حساسیت بالا به هزینه‌ی تخفیف روی حاشیه سود کم.

## ۴. پرسونای مشتریِ نهایی هر فروشگاه (نمونه سیگنال‌ها)

| پرسونا | سیگنال غالب | اقدام مناسب |
|---|---|---|
| فقط یادآوری می‌خواهد | خرید منظم قبلی، بدون واکنش به تخفیف | یادآوری ساده بدون تخفیف |
| حساس به ارسال رایگان | چند بار سبد رهاکرده وقتی هزینه ارسال دیده | پیشنهاد ارسال رایگان مشروط |
| بدون تخفیف هم می‌خرد | نرخ تبدیل بالا بدون کد تخفیف در سابقه | عدم ارسال تخفیف؛ صرفاً معرفی محصول جدید |
| نیاز به BNPL | ارزش سبد بالا، خرید در آستانه رها شدن در مرحله پرداخت | پیشنهاد پرداخت اقساطی/اعتباری |
| نباید زیاد پیام بگیرد | نرخ باز کردن پایین، بدون خرید پس از چند پیام اخیر | سکوت (do-not-disturb) یا کاهش فرکانس |
| ریسک ریزش امروز | مدت طولانی از آخرین تعامل + الگوی تکرار خرید نزدیک به پایان عمر | پیام فوری با پیشنهاد بازگشت (win-back) |

## ۵. تعریف Next-Best-Action Engine

### ۵.۱ ورودی‌ها (Inputs)
برای هر مشتری، ترکیبی از:
1. **پروفایل مشتری:** شناسه، تاریخ عضویت، کانال ترجیحی، محدودیت تماس (opt-out، حداکثر پیام در هفته).
2. **تاریخچه‌ی سفارش‌ها:** تعداد، مبلغ، تاریخ آخرین خرید، استفاده از کد تخفیف در گذشته، بازه‌ی تکرار خرید.
3. **سبد فعلی/رهاشده:** آیتم‌ها، مبلغ، مرحله‌ی رهاشدن (مشاهده قیمت ارسال، مرحله پرداخت).
4. **مکالمات (دایرکت/واتساپ):** پیام‌های اخیر، سوال قیمت، شکایت، عدم پاسخ.
5. **تعامل استوری/شبکه اجتماعی:** واکنش، ری‌اکشن، بازدید بدون خرید.
6. **تاریخچه‌ی کمپین‌های قبلی:** چه پیشنهادی داده شد، چه واکنشی داشت (باز شد؟ خرید کرد؟ نادیده گرفت؟).

### ۵.۲ منطق تصمیم (پایپلاین)

```
داده‌ی خام مشتری
      │
      ▼
[۱. استخراج سیگنال]   → RFM (Recency/Frequency/Monetary)، حساسیت به تخفیف،
                          حساسیت به ارسال رایگان، ریسک ریزش، فرکانس تماس مجاز،
                          سیگنال مکالمه (نیت خرید از متن دایرکت/واتساپ)
      │
      ▼
[۲. امتیازدهی]         → هر سیگنال به شکل امتیاز عددی نرمال‌شده (۰ تا ۱)
      │
      ▼
[۳. انتخاب از کاتالوگ اقدام]  → قوانین اولویت‌دار + امتیاز، از بین:
   reminder (یادآوری ساده) | free_shipping | discount_percent |
   cashback | bnpl_offer | bundle_offer | vip_no_discount |
   win_back (پیام فوری بازگشت) | do_not_disturb (سکوت)
      │
      ▼
[۴. انتخاب کانال]      → بر اساس کانال ترجیحی مشتری و نوع پیام
      │
      ▼
[۵. اعمال محدودیت فرکانس] → چک opt-out و سقف پیام هفتگی؛ در صورت عبور → do_not_disturb
      │
      ▼
[۶. تولید پیام فارسی]  → قالب متنی مناسب کانال (کوتاه برای دایرکت/واتساپ، رسمی‌تر برای پیامک)
      │
      ▼
[۷. ثبت بازخورد]       → نتیجه‌ی اقدام (باز شد/خرید شد/نادیده گرفته شد) ذخیره می‌شود
                          برای بهبود امتیازدهی در دور بعد
```

### ۵.۳ خروجی‌ها (Outputs)

برای هر مشتری یک آبجکت تصمیم:

```json
{
  "customer_id": "c_1029",
  "recommended_action": "free_shipping",
  "channel": "whatsapp",
  "urgency": "medium",
  "message_fa": "سلام مریم جان 🌸 سبدت هنوز منتظرته! امروز ارسال رایگانه، دوست داری تکمیلش کنیم؟",
  "reasoning": [
    "سبد رهاشده در ۴۸ ساعت اخیر",
    "۲ بار قبلی هنگام دیدن هزینه ارسال، سبد را رها کرده",
    "بدون تخفیف نرخ تبدیل پایین؛ اما به ارسال رایگان حساس است"
  ],
  "confidence": 0.78,
  "do_not_disturb": false
}
```

### ۵.۴ کاتالوگ اقدام (Action Catalog) — نسخه MVP

| اقدام | شرط فعال‌سازی (خلاصه) | هزینه برای فروشنده |
|---|---|---|
| `reminder` | خرید منظم قبلی، بدون سیگنال حساسیت به تخفیف/ارسال | صفر |
| `free_shipping` | سبد رهاشده + سابقه‌ی حساسیت به هزینه ارسال | کم |
| `discount_percent` | نرخ تبدیل پایین بدون تخفیف + ارزش طول عمر مشتری بالا | متوسط |
| `cashback` | مشتری تکرارشونده که به بازگشت پول حساس‌تر از تخفیف آنی است | متوسط |
| `bnpl_offer` | ارزش سبد بالا نسبت به میانگین + رهاشدن در مرحله پرداخت | صفر (کارمزد از پرداخت) |
| `bundle_offer` | چند آیتم مرتبط در سبد/سابقه | کم |
| `vip_no_discount` | خرید بدون تخفیف در سابقه + فرکانس بالا | صفر |
| `win_back` | مدت زیاد از آخرین خرید نزدیک به پایان چرخه‌ی معمول | بالا (ریسک از دست رفتن) |
| `do_not_disturb` | opt-out، یا عبور از سقف فرکانس، یا نرخ باز کردن پایین اخیر | صفر |

### ۵.۵ کانال‌ها

- **دایرکت اینستاگرام** — لحن صمیمی، کوتاه، ایموجی محدود
- **واتساپ** — لحن نیمه‌رسمی، امکان لینک/تصویر محصول
- **پیامک** — کوتاه‌ترین حالت، بدون ایموجی، برای پیام‌های حساس به فوریت (مثل win_back)
- (فاز بعد) **ایمیل** برای گزارش/فاکتور، **تلگرام**

## ۶. معیار موفقیت (نسخه MVP)

- کاهش نرخ ارسال تخفیف عمومی به مشتریانی که بدون تخفیف هم خرید می‌کنند.
- افزایش نرخ بازگشت مشتریان در ریسک ریزش پس از دریافت win_back به‌موقع.
- کاهش نرخ آن‌فالو/شکایت از اسپم با اعمال محدودیت فرکانس (`do_not_disturb`).
- زمان لازم برای گرفتن تصمیم «با این مشتری چه کنم؟» از دستی (چند دقیقه در روز برای هر مشتری) به لحظه‌ای (API).

## ۷. خارج از محدوده‌ی MVP

- اجرای خودکار ارسال پیام (فاز MVP فقط تصمیم و متن پیشنهادی تولید می‌کند؛ ارسال واقعی نیازمند اتصال به API رسمی واتساپ بیزینس/اینستاگرام است که در فاز بعد اضافه می‌شود).
- مدل یادگیری ماشین آموزش‌دیده روی داده واقعی (MVP از موتور قانون‌محور + امتیازدهی استفاده می‌کند؛ حلقه بازخورد برای فاز بعد آماده‌سازی شده).
- پنل مدیریتی گرافیکی (فاز بعد؛ MVP فقط API و مستندات دارد).

## ۸. فازبندی

1. **فاز ۰ (این نسخه):** PRD + معماری + MVP فنی (API تصمیم‌ساز) + لندینگ برای اعتبارسنجی ایده.
2. **فاز ۱:** اتصال به منبع داده واقعی (اینستاگرام/واتساپ بیزینس/فروشگاه‌ساز)، پنل مدیریتی.
3. **فاز ۲:** حلقه‌ی بازخورد و یادگیری از نتیجه‌ی کمپین‌ها، مدل امتیازدهی تطبیقی.
4. **فاز ۳:** ارسال خودکار چندکاناله + گزارش‌گیری.
